# Critic — Travelback (2026-05-04)

## Summary

Travelback is a well-executed single-purpose tool with clear design intent. The architecture is sound for its current scope. This review focuses on inconsistencies, over-engineering risks, and areas where stated design diverges from implementation.

## Findings

### 1. Stated "distance-based interpolation" but scene system is percent-based — LOW risk, HIGH confidence
**Files**: `.context/project/02-architecture.md`, `src/lib/camera.ts`, `src/types.ts:69-71`
**Issue**: The architecture doc emphasizes "distance-based interpolation" for uniform speed. The scene system uses `startPercent/endPercent` (0-1), which is progress-based, not distance-based. While `interpolateAlongTrack` correctly maps progress to distance, the scene boundaries are defined in progress space, meaning scene lengths are proportional to distance traveled — which is the intended behavior. No actual inconsistency, but the docs could be clearer.
**Suggestion**: Clarify that "percent" in the scene system refers to distance-based progress.

### 2. Default scene generation is triggered only on export, not on track load — MEDIUM risk, HIGH confidence
**Files**: `src/lib/useExportController.ts:161-163`, `src/app/page.tsx:128`
**Issue**: When a track is loaded, `scenes` is initialized to `[]`. Default scenes are generated in `exportTrack` only when scenes is empty. This means during playback preview, the user sees the default follow camera without scenes, but the exported video uses cinematic scenes. The user may not realize their video will look different from the preview.
**Suggestion**: Either auto-generate default scenes on track load (so preview matches export) or clearly indicate in the UI that scenes will be auto-generated on export.

### 3. i18n key type safety is loose — LOW risk, HIGH confidence
**File**: `src/lib/i18n.ts:1814`
**Issue**: `t()` function accepts `TranslationKey` but falls back to returning the key itself if not found: `translations[locale][key] || translations.en[key] || key`. This silently returns raw keys for missing translations rather than logging a warning.
**Suggestion**: Add a development-mode warning when a key falls through to the key string.

### 4. React strict mode double-mount compatibility — LOW risk, MEDIUM confidence
**Files**: `src/components/MapView.tsx:760-854`
**Issue**: Map initialization in useEffect creates a new MapLibre instance on mount and destroys it on cleanup. React 19 strict mode double-mounts components, which would create and destroy the map twice. The `mapRetryNonce` dependency controls re-creation. This is handled correctly — the cleanup properly removes the map.
**Suggestion**: No change needed — the cleanup is thorough.

### 5. Export memory estimation may underestimate — LOW risk, MEDIUM confidence
**File**: `src/lib/videoEncoder.ts:50-66`
**Issue**: The 8x multiplier for raw frame bytes accounts for double-buffering and codec intermediates. For 4K exports, this may still underestimate because MapLibre's WebGL context has its own GPU memory that isn't accounted for. The MAX_IN_MEMORY_EXPORT_BYTES (256MB) threshold may be too generous for mobile devices.
**Suggestion**: Consider device-aware memory limits or at minimum warn users on 4K portrait exports.

### 6. Playback accumulates time from performance.now() — LOW risk, HIGH confidence
**File**: `src/lib/usePlaybackController.ts:98-151`
**Issue**: The accumulator-based progress tracking records `startTimestampRef` and computes progress from elapsed wall-clock time. This correctly handles background tab throttling (where rAF is paused) — when the tab returns, the elapsed time jumps forward, correctly skipping the throttled duration. This is intentional and well-implemented.
**Suggestion**: None needed.

### 7. Error boundary catches but error codes are not surfaced — LOW risk, MEDIUM confidence
**File**: `src/components/ErrorBoundary.tsx:26-29`
**Issue**: `componentDidCatch` logs the error and preserves the component stack, but the error boundary's "Try Again" button just resets state. If the error was caused by a specific track or state, re-rendering with the same state will likely re-trigger the error. The "Reload Page" button is the more reliable recovery.
**Suggestion**: Consider clearing the track state on "Try Again" to provide a genuine recovery path.

### 8. JourneyCreator only rendered when track is null — LOW risk, HIGH confidence
**File**: `src/app/page.tsx:556-564`
**Issue**: JourneyCreator is conditionally rendered only when `!track && isCreatingJourney`. If the user is creating a journey and then loads a file, the journey creation is silently cancelled (since `handleTrackLoaded` calls `loadTrackIntoSession` which sets `isCreatingJourney=false`).
**Suggestion**: This is correct behavior — loading a file should exit journey mode.

### 9. Multiple localStorage keys for theme/map style tracking — LOW risk, MEDIUM confidence
**File**: `src/app/page.tsx:57-60`
**Issue**: Four localStorage keys track theme and map style state: `travelback-theme`, `travelback-theme-explicit`, `travelback-mapstyle`, `travelback-mapstyle-explicit`. The "explicit" flags track whether the user manually chose a value vs. system-derived. This complexity exists to handle the interplay between system color scheme changes and user preferences.
**Suggestion**: Acceptable but complex. Consider a single JSON object in localStorage to reduce key count.

### 10. Test stub utility exists in production code — LOW risk, HIGH confidence
**File**: `src/lib/test-stub.ts`
**Issue**: `isLocalExportTestStubEnabled()` is checked in both useExportController and ExportPanel. This allows bypassing real video export for testing. The function checks for a URL parameter or env variable.
**Suggestion**: Ensure this is tree-shaken in production builds or gated behind `NODE_ENV === 'development'`.
