# Designer Review — Travelback (2026-05-04)

## Summary

The UI is well-designed with consistent theming, good responsive behavior, and thoughtful accessibility attributes. Key areas for improvement are in focus management, some ARIA gaps, and mobile touch targets.

## Findings

### 1. Focus-visible outline consistently applied — LOW risk, HIGH confidence
**Files**: All interactive components
**Issue**: Buttons and interactive elements consistently use `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[rgb(var(--gl))]`. This provides good keyboard navigation visibility.
**Suggestion**: None needed — well-implemented.

### 2. Minimum touch target size of 44px (min-h-11 min-w-11) — LOW risk, HIGH confidence
**Files**: `src/components/FileUpload.tsx`, `src/components/ExportPanel.tsx`, `src/components/Controls.tsx`
**Issue**: Interactive elements use `min-h-11` (44px) for touch targets, meeting WCAG 2.5.5 (Target Size) at the AA level.
**Suggestion**: None needed.

### 3. ARIA landmarks properly used — LOW risk, HIGH confidence
**Files**: `src/app/page.tsx:512,570`
**Issue**: The main element has `id="app"`. The workspace status div has `role="status" aria-live="polite"` for screen reader announcements. ModalDialog uses `labelledBy` prop.
**Suggestion**: None needed.

### 4. Export panel progress bar has ARIA attributes — LOW risk, HIGH confidence
**File**: `src/components/ExportPanel.tsx:304`
**Issue**: Progress bar has `role="progressbar"`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and `aria-label`. Correct.
**Suggestion**: None needed.

### 5. Map container uses aria-hidden when no track — LOW risk, HIGH confidence
**File**: `src/components/MapView.tsx:1183-1184`
**Issue**: Map is `aria-hidden` when no track is loaded and no error is shown. It also uses `inert` attribute to prevent keyboard focus. This correctly prevents screen readers from navigating into an empty map.
**Suggestion**: None needed.

### 6. Error states use role="alert" — LOW risk, HIGH confidence
**Files**: `src/components/FileUpload.tsx:157,290`, `src/components/MapView.tsx:1188`, `src/components/ExportPanel.tsx:414,419`
**Issue**: Error messages use `role="alert"` for screen reader announcement. Warning messages also use `role="alert"`.
**Suggestion**: None needed.

### 7. Dark/light mode properly implemented — LOW risk, HIGH confidence
**Files**: `src/app/page.tsx:90-101,246-271`, `src/app/globals.css`
**Issue**: Theme detection reads from document attribute (set by bootstrap script), localStorage, and matchMedia. System theme changes are listened to via matchMedia event listener. Manual overrides are properly persisted.
**Suggestion**: None needed.

### 8. ModalDialog focus trap — MEDIUM risk, MEDIUM confidence
**File**: `src/components/ModalDialog.tsx`
**Issue**: ModalDialog is used for ExportPanel, GoogleGuide, and trim confirmation. It should trap focus within the dialog and restore focus on close. Without reading the full implementation, the `labelledBy` prop suggests ARIA dialog role is used.
**Suggestion**: Verify that focus trap and focus restoration are implemented in ModalDialog.

### 9. Color contrast may be insufficient for some text — LOW risk, MEDIUM confidence
**Files**: Various components using `var(--t4)` and `var(--t5)`
**Issue**: Lower-contrast text colors (--t4, --t5) are used for hints and secondary text. Without seeing the actual CSS variable values, these may not meet WCAG AA contrast ratio (4.5:1) in all theme modes.
**Suggestion**: Audit contrast ratios for --t3, --t4, --t5 in both light and dark modes.

### 10. Reduced motion preference not respected — LOW risk, MEDIUM confidence
**Files**: `src/app/globals.css`
**Issue**: The app uses CSS transitions and animations (marker-pulse, landing-preview-image hover). There's no evidence of `prefers-reduced-motion` media query usage.
**Suggestion**: Add `@media (prefers-reduced-motion: reduce)` rules to disable animations.

### 11. RTL layout not supported — LOW risk, HIGH confidence
**Files**: All components
**Issue**: The app supports 5 locales (en, ko, ja, zh, es) but none are RTL languages. This is acceptable for the current locale set.
**Suggestion**: No change needed — no RTL languages are supported.

### 12. Loading/empty states present — LOW risk, HIGH confidence
**Files**: `src/components/FileUpload.tsx`, `src/components/MapView.tsx`
**Issue**: Loading state shows a spinner during file parsing. Empty state shows the upload overlay. Map error state shows retry options. Export states cover idle/exporting/done.
**Suggestion**: None needed — states are well-covered.
