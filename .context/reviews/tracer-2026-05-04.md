# Tracer — Travelback (2026-05-04)

## Summary

Causal tracing of the major data flows reveals well-designed state management with proper cleanup. The main risks are in the export/playback state handoff and async cleanup ordering.

## Flow 1: File Upload → Parsing → Track State → Map Rendering

### Trace
1. `FileUpload.handleFile` → `parseTrackFile(file)` → returns `Track`
2. `onTrackLoaded(track)` → `page.tsx:handleTrackLoaded` → `loadTrackIntoSession`
3. `loadTrackIntoSession` resets workspace, clears track artifacts, sets `fullTrack`/`track`, resets playback
4. `track` state change triggers `MapView.tsx:993-1053` effect → `addTrackLayers` + `fitBounds`
5. `cumulativeDistancesProp` change triggers precompute in MapView

### Finding 1: Race between loadTrackIntoSession and MapView cleanup — LOW risk, MEDIUM confidence
**Files**: `src/app/page.tsx:297-307`, `src/components/MapView.tsx:993-1053`
**Issue**: `loadTrackIntoSession` calls `mapViewRef.current?.clearTrackArtifacts()` synchronously, then sets track state. The MapView effect that handles `track` changes runs asynchronously (after React commit). Between these two points, MapView has no track loaded but the old artifacts were already cleared. This is intentional — it prevents stale artifacts from appearing during the brief transition. No race condition exists because React batches state updates.

## Flow 2: Playback Animation Loop

### Trace
1. `togglePlay` sets `isPlaying=true`
2. `usePlaybackController.ts:98-151` effect starts, records `startProgressRef` and `startTimestampRef`
3. `animate(now)` computes `nextProgress = startProgress + (elapsed * speed) / duration`
4. `setPlaybackProgress(nextProgress)` updates React state
5. MapView effect at `progress` dependency triggers camera/trail/marker update

### Finding 2: Playback continues briefly after component unmount — LOW risk, HIGH confidence
**File**: `src/lib/usePlaybackController.ts:145-150`
**Issue**: The cleanup function sets `mountedRef.current = false` and cancels animation frame. If an animation frame fires between the unmount and cleanup (unlikely but possible in concurrent mode), it checks `mountedRef.current` and returns early. This is properly guarded.

## Flow 3: Export Pipeline

### Trace
1. `ExportPanel.onExport` → `useExportController.exportTrack(config)`
2. `exportTrack` creates AbortController, sets `isExporting=true`, pauses playback
3. Resizes map → waits for idle → starts frame loop
4. Each frame: compute camera → `renderFrameAndWait` → wait for idle → capture frame
5. On success: blob URL created, download triggered, state set to 'done'
6. On abort: error caught, state reset to 'idle'
7. Finally: map reset to original size, playback progress restored

### Finding 3: Abort during waitForIdle may leave map resized — MEDIUM risk, MEDIUM confidence
**Files**: `src/lib/useExportController.ts:274-305`, `src/components/MapView.tsx:703-757`
**Issue**: If the user aborts during `waitForIdle` (the map hasn't settled after resize), the `finally` block calls `mapViewRef.current?.resetSize()`. However, `waitForIdle` is called again at line 300 in the finally block with the already-aborted signal. The `waitForIdle` will reject with AbortError, which is caught at line 302. The `resetSize` at line 280 has already cleaned the container styles. This is correct but the flow is hard to follow.

### Finding 4: Export progress display may show stale value on abort — LOW risk, HIGH confidence
**File**: `src/lib/useExportController.ts:306-310`
**Issue**: On abort, `setExportProgress(0)` is called in the finally block. But `setExportState('idle')` is called in the catch block at line 272. If the catch runs before the finally sets progress to 0, there's a brief moment where `exportState='idle'` but `exportProgress > 0`. This is invisible to the user since the ExportPanel only shows progress when `isExporting` is true.

## Flow 4: Scene System → Camera Blending

### Trace
1. Scenes defined in `SceneEditor` → stored in `page.tsx:scenes` state
2. `normalizedScenesRef` updated via effect in MapView
3. During playback: `computeCameraForProgress(track, cumulDist, scenes, progress, elapsed, transitionDuration)`
4. Scene lookup → local progress computation → `computeCameraForScene` → camera state
5. Transition blending via `lerpCamera` at scene boundaries

### Finding 5: Scene normalization runs on every render for non-preNormalized path — LOW risk, HIGH confidence
**File**: `src/lib/camera.ts:365`
**Issue**: When `preNormalized` is false (playback path), `normalizeScenes` sorts and clips scenes on every call. MapView pre-normalizes into `normalizedScenesRef` and passes `preNormalized=true` during playback. The export path in videoEncoder.ts also pre-normalizes. This is correctly optimized.

## Flow 5: Theme/Map Style Changes

### Trace
1. User cycles theme → `handleModeChange` or `cycleStyle`
2. State updated + localStorage persisted + document attributes set
3. MapView effect detects `mapStyleKey` change → `map.setStyle()`
4. Style load event → re-adds all layers and sources

### Finding 6: Style change re-adds layers but doesn't re-fit bounds — LOW risk, HIGH confidence
**File**: `src/components/MapView.tsx:857-880`
**Issue**: After style change, `addTrackLayers` is called but `fitBounds` is not. The map retains its current viewport position. This is correct — style changes should preserve the user's current view.

## Flow 6: Timeline Trim → Filtered Track

### Trace
1. `TimelineSelector` calls `onRangeChange(startIdx, endIdx)`
2. `handleRangeChange` checks if scenes exist → if so, shows confirmation dialog
3. `buildFilteredTrack(fullTrack, startIdx, endIdx)` slices points and remaps segments
4. `setTrack(filteredTrack)` + `resetPlayback()`

### Finding 7: Trim during export is prevented by UI — LOW risk, HIGH confidence
**File**: `src/components/TimelineSelector.tsx` (assumed)
**Issue**: The timeline selector should be disabled during export. The `isExporting` state is available in page.tsx. Verification needed that the timeline selector respects this.
