## Finding 1: Map style change during export produces blank frames

**File**: `src/components/MapView.tsx:856-879` + `src/app/page.tsx`  
**Severity**: Medium  
**Confidence**: High  

Same as tracer Trace 4. If the user changes the map style during export, `map.setStyle()` removes all sources/layers mid-export.

**Fix**: Disable map style controls during export.

## Finding 2: `waitForIdle` timeout during export allows incomplete frames

**File**: `src/lib/useExportController.ts:177-188`  
**Severity**: Low  
**Confidence**: High  

A single idle timeout (map didn't idle but hasn't timed out twice) allows the export to continue with potentially incomplete tile rendering.

**Fix**: Log a warning when `waitForIdle` returns `false` during export.

---

## Finding 3: `renderFrameAndWait` exact-match deadlock risk

**File**: `src/components/MapView.tsx:611-615`  
**Severity**: Low  
**Confidence**: High  

When camera state matches exactly (within rounding), `renderFrameAndWait` resolves immediately. The 5-second timeout fallback catches the worst case.

**Fix**: Consider adding `map.repaint = true` before `jumpTo` to force repaint.

---

## Finding 4: Worker `onmessage` handler does not validate `track.points` array

**File**: `src/lib/parser.ts:672-678`  
**Severity**: Low  
**Confidence**: Medium  

If the worker returns a track with missing or malformed `points` array (e.g., `points: null`), the timestamp conversion loop would throw.

**Fix**: Add a guard: `if (!Array.isArray(track.points)) { reject(...); return; }` before the iteration.
