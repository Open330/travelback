## New supported root

### CORE10-01 — Paused elapsed-sensitive camera stays stale after a duration change

Severity: **Low**
Confidence: **High**

Evidence:

- `src/components/MapView.tsx:319-325` updates `durationRef`.
- `src/components/MapView.tsx:729-747` derives scene elapsed time from
  `progressRef.current * durationRef.current`.
- `src/components/MapView.tsx:1097-1173` applies the camera, but the effect
  excludes `duration`.
- `src/app/page.tsx:720-725` passes raw `setDuration`; unlike scene and
  transition commits, it does not publish the resulting camera.

At a nonzero paused progress inside Orbit, Overview, or Bird's Eye, changing
the animation duration changes the elapsed-time input but does not run the
effect that consumes it. The visible camera therefore retains the old bearing
until playback resumes, progress changes, or another camera-refreshing action
occurs. Export uses the new duration immediately, so the paused preview and
export request disagree.

Fix: route duration changes through an application handler that computes and
applies the camera with the proposed duration when Follow is on. Preserve a
manual camera when Follow is off. Add focused regression evidence for both
ownership paths.

This is distinct from historical P1-8, which introduced ref indirection to
avoid duration-driven effect reruns; that performance task did not cover the
paused-camera correctness gap created by the new ownership model.
