# Debugger Review — Travelback (2026-05-04)

## Summary

The codebase handles most error paths well. The main latent bug risks are in async cleanup ordering, edge cases in interpolation, and potential issues with the export/playback state handoff.

## Findings

### 1. Export playback progress restore may race with unmount — LOW risk, MEDIUM confidence
**File**: `src/lib/useExportController.ts:306-310`
**Issue**: In the finally block, `setPlaybackProgress(preExportProgress)` is called after checking `mountedRef.current`. If the component unmounts between the check and the setState call (extremely unlikely in practice), React would warn about setting state on an unmounted component. The mountedRef guard prevents this in the common case.
**Suggestion**: No change needed — the ref guard is sufficient.

### 2. wrapLngNear while loop could theoretically infinite-loop — LOW risk, HIGH confidence
**File**: `src/lib/interpolate.ts:14-18`
**Issue**: `wrapLngNear` uses `while (adjusted - referenceLng > 180) adjusted -= 360`. If `referenceLng` or `adjusted` is NaN or Infinity, the loop would not terminate. However, all callers validate coordinates with `Number.isFinite` before reaching this point.
**Suggestion**: Add a guard: `if (!Number.isFinite(referenceLng) || !Number.isFinite(nextLng)) return nextLng`.

### 3. haversineDistance clamps to avoid NaN from floating point — LOW risk, HIGH confidence
**File**: `src/lib/interpolate.ts:26`
**Issue**: `Math.min(1, sinLat * sinLat + ...)` prevents the argument to `Math.asin(Math.sqrt(h))` from exceeding 1.0 due to floating point imprecision. Without this clamp, `Math.sqrt` could receive a value slightly above 1, producing NaN.
**Suggestion**: Well-implemented guard. No change needed.

### 4. findDistanceIndexAtOrAfter returns 0 for empty arrays — LOW risk, HIGH confidence
**File**: `src/lib/interpolate.ts:58`
**Issue**: Returns 0 when `cumulativeDistances.length === 0`. Callers must ensure the array is non-empty. This is consistently guarded at call sites.
**Suggestion**: No change needed.

### 5. Export canvas capture may fail silently on GPU context loss — MEDIUM risk, LOW confidence
**File**: `src/lib/videoEncoder.ts:162`
**Issue**: `videoSource.add(timestamp, frameDuration)` captures the canvas. If the WebGL context is lost during export (e.g., GPU reset), the captured frame would be blank. There is no explicit check for context loss. MapLibre may fire an error event, but the export loop doesn't listen for it.
**Suggestion**: Add a `webglcontextlost` event listener on the canvas during export that triggers abort.

### 6. Race condition between style change and track load — LOW risk, MEDIUM confidence
**File**: `src/components/MapView.tsx:857-880,993-1053`
**Issue**: If the user changes the map style while a track is being loaded, both effects fire. The style change effect uses `map.once('style.load')` to re-add layers. The track load effect also waits for style to be ready. Both effects are idempotent (they check for existing sources/layers before adding), so the order doesn't matter. No race condition.
**Suggestion**: No change needed — idempotent layer management prevents conflicts.

### 7. AbortController in exportTrack is replaced on each call — LOW risk, HIGH confidence
**File**: `src/lib/useExportController.ts:143-144`
**Issue**: `exportAbortRef.current = abortController` replaces any previous controller. Since `isExporting` prevents multiple simultaneous exports (the ExportPanel disables the button), this is safe. The previous controller's signal would already be handled.
**Suggestion**: No change needed.

### 8. Marker element reuse across track sessions — LOW risk, HIGH confidence
**File**: `src/components/MapView.tsx:968-990`
**Issue**: `ensureMarker` creates the marker DOM element once and reuses it. When `clearTrackArtifacts` is called, `markerRef.current?.remove()` removes the marker from the map but doesn't destroy `markerEl.current`. On the next track load, `ensureMarker` reuses the existing element. This is correct — the DOM element is recycled.
**Suggestion**: No change needed.

### 9. parseOptionalDate accepts invalid Date objects — LOW risk, MEDIUM confidence
**File**: `src/lib/parse-utils.ts:18-22`
**Issue**: `new Date(value)` may produce a Date with an invalid time (NaN). The check `Number.isNaN(parsed.getTime())` correctly catches this. However, `new Date('')` produces an invalid Date, which is handled. `new Date(0)` produces epoch, which is correct.
**Suggestion**: No change needed.

### 10. TextDecoder with fatal:false silently replaces invalid UTF-8 — LOW risk, HIGH confidence
**File**: `src/lib/parser.ts:229`
**Issue**: `new TextDecoder('utf-8', { fatal: false })` replaces invalid UTF-8 bytes with the replacement character (U+FFFD). This prevents crashes on malformed JSON files but may produce invalid JSON that fails `JSON.parse`.
**Suggestion**: No change needed — the JSON.parse error handling covers this.

### 11. Export frame loop doesn't check canvas validity per frame — LOW risk, MEDIUM confidence
**File**: `src/lib/videoEncoder.ts:135-166`
**Issue**: The canvas element is captured once at the start of `exportVideo`. If the canvas is removed from the DOM or its context is destroyed during export, `videoSource.add()` may fail. The AbortSignal check at the top of each loop iteration catches user-initiated cancellation but not canvas destruction.
**Suggestion**: Consider wrapping `videoSource.add()` in try/catch with a meaningful error message.

### 12. downloadVideo fallback anchor cleanup — LOW risk, HIGH confidence
**File**: `src/lib/videoEncoder.ts:207,236-257`
**Issue**: Module-level `prevFallbackAnchor` tracks the previous fallback download anchor. On rapid clicks, the previous anchor is removed before creating a new one. The setTimeout(100ms) cleanup handles Safari's download timing requirements. The identity check `prevFallbackAnchor === a` prevents stale HMR references from causing issues.
**Suggestion**: Well-implemented edge case handling.
